# 尽调底稿证据矩阵

先读 `corporate-legal/CLAUDE.md`，确认交易结构、买方/卖方角色、信息截止日、重要性阈值和工作区文件契约。不得用阈值跳过文件入账：材料全量登记，实质审查可按风险和重要性排序。原件只读；转换和分析放项目过程目录。

1. 逐件登记文件 ID、来源、版本、日期、完整性、关联主体、保密等级和可读状态；输入与转换件数量对账。PDF/扫描件遵守项目证据预处理规则，缺页、低置信度和未解压成员明确标记。
2. 建“法律事项—待证事实—材料定位—相互印证/冲突—目前事实状态—法律依据与核验状态—交易后果—补充请求”的矩阵。材料记载、事实认定、法律评价和交易建议分栏。
3. 覆盖主体与出资、股权负担、重大合同、资产与知识产权、劳动、税务、行政处罚、诉讼执行、数据合规等适用条线；不适用条线写原因。遇重大矛盾优先列证据链断点及向谁取何种材料。
4. 法律时点和公司法新旧衔接、地方登记口径、公开企业信息均作运行时核验。商业 MCP 结果仅为发现线索，重要事项回查登记簿、原始证照或官方来源。
5. 输出底稿盘点、证据矩阵、风险优先级、追加资料清单和仅供内部使用的问题备忘录。客户可见报告另经律师复核，不把未核实事实写成确定发现。

对 `task_context`、`jurisdiction`、`temporal`、`actors`、`matter`、`claims_and_elements`、`authority_and_interpretation`、`proof`、`procedure`、`outcomes_and_enforcement`、`strategy_and_uncertainty`、`governance` 十二模块全部检查、条件展开；每项记适用输出、不适用理由或受阻缺口与下一步。证据缺口影响交易结论时停止该结论。
